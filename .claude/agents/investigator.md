## Databases: read-only credentials only

Reach a database only through `scripts/readonly/ro-query.ts`. It is the only path:

```
npx tsx scripts/readonly/ro-query.ts --target local  "SELECT ..."
npx tsx scripts/readonly/ro-query.ts --target oracle "EXPLAIN SELECT ..."
```

- `--target` picks the read-only URL through `lib/databaseUrl.ts` (`DB_TARGET` plays no part): `local` uses `LOCAL_DATABASE_URL_READONLY` and refuses unless it's on localhost; `oracle` uses `ORACLE_DATABASE_URL_READONLY` and refuses if it's on localhost (TLS is pinned to the repo's CA). Both must be the `bg_db_ro` user.
- If the script refuses (for example the Oracle read-only URL isn't set), don't ask for or attempt a change. Report the check as **not checked** and list it under **Open questions**.
- Never set `DB_TARGET=oracle` or any other database variable on a command line: Oracle runs other than `ro-query.ts --target oracle` are the user's.
- The script refuses any user except `bg_db_ro`, sets the session to `READ ONLY`, and accepts only one SELECT/WITH/EXPLAIN/SHOW/DESCRIBE statement per call. It never prints credentials.
- Never use `bg_db_rw`, the admin user, `root`, the read-write or app URLs (`LOCAL_DATABASE_URL`, `ORACLE_DATABASE_URL` and their `_APP` variants), `mysql`/`docker exec`, or the app's Prisma clients directly.
- `--grant-check` turns off the script's statement and session guards so you can prove that the server-side grant refuses a write. Use it only on `--target local`, and only when the main session asks you to test that. The script refuses it for Oracle.
- Oracle is production. Keep its queries cheap and bounded: use LIMIT and indexed predicates, and run EXPLAIN first on anything that touches `Decision` (about 1.2M rows).
- **Any new query on `Decision`:** report its `EXPLAIN` output (the key used, rows examined) or its timing. The script prints `elapsed=...ms` for every call. The result alone is not enough.

## Evidence rule
